# 扫码绑定宿主机

## 使用流程

1. 推荐在电脑的 `server` 目录运行 `npm run host`，同时启动新版后端和本机 Codex 接入端，自动保存稳定的主机令牌。若分开启动后端，则设置稳定的 `AUTH_TOKEN`，保持 `HOST=0.0.0.0`，并另行启动 Agent。浏览器打开启动日志中的 `/pair/` 地址（默认 `http://localhost:4820/pair/`）。网页显示真实 Agent 在线状态，绑定成功不代表 Agent 已接入。
2. 手机和电脑连接同一 Wi-Fi / 局域网。在网页“手机将连接到”中选择可达地址，普通局域网网卡优先于虚拟网卡；切换地址会生成新二维码。
3. 在新版 APP 的“连接设置”点击“扫码绑定宿主机”，或点击“主机与连接”右上角扫码图标。首次使用需要允许相机权限。
4. 对准网页二维码，核对电脑名称与地址，可以修改手机名称，然后点击“确认绑定”。APP 保存独立凭据并自动重连，网页显示绑定成功和设备名称。
5. 在网页“已绑定设备”中可解除单台设备的绑定，现有 WebSocket 立即断开，后续请求被拒绝。设备需要重新扫码才能恢复访问。

相机不可用时，可以复制网页上的绑定链接，在 APP 扫码页“粘贴绑定链接”。原有手动填写地址、端口与令牌的连接方式仍可使用。绑定新主机将替换 APP 当前的中心服务连接，不是同时连接多个中心服务。

## 界面

网页沿用 Nightflight Studio 的瓷白、深墨和青柠。桌面分为深色导航、二维码卡片、三步引导、主机地址与设备管理；窄屏自动变为单列。APP 使用取景框、确认主机卡片和绑定成功页。所有二维码、主机地址、设备列表和绑定结果来自实际后端。

二维码有效期为两分钟，刷新后旧的未使用二维码立即失效。网页不自动刷新，避免正在扫码的手机突然失效。一次二维码绑定一台设备；仅同一手机的同一请求允许重试，以恢复网络中断时丢失的响应。已绑定设备不受二维码过期或刷新影响。

APP 保存独立的安装标识，修改手机名称、重新扫码、重启 APP 或覆盖升级不会改变标识。服务端以主机与安装标识建立唯一约束，重复绑定返回 `409 / DEVICE_ALREADY_PAIRED`，原凭据保持可用。解除绑定后可再次绑定。旧版绑定在新版 APP 首次重扫时可用原凭据补上身份，不新建一条记录；缺少安装标识的旧版 APP 绑定请求返回 `426`，需升级 APP。清除 APP 数据或卸载后重装属于新的安装；不使用 IMEI 等硬件指纹，不依据名称或 IP 合并不同设备。

## 网络与凭据边界

- 管理网页及其管理接口仅允许宿主机通过 `localhost`、`127.0.0.1` 或 `[::1]` 访问，校验实际来源、Host 和 Origin，并禁用缓存与跨站嵌入。
- QR 内容为 `xiaomeng://pair?v=1&server=…&name=…&code=…&expires=…`，只包含局域网地址、主机名称、一次性随机码和有效期，不包含 `AUTH_TOKEN`。
- APP 确认后向该主机 `/pair/exchange` 提交临时码、随机重试标识、安装标识、手机名称和平台，取得独立设备令牌。APP 不跟随重定向。只有扫码地址与当前已保存地址完全相同时，才携带该主机的旧设备凭据来迁移旧绑定；不发送主令牌或其他主机的凭据。
- 服务端 SQLite `paired_devices` 仅保存设备令牌的 SHA-256 摘要及所属主令牌摘要。设备令牌可以调用 APP 的 REST / WebSocket 功能，不能注册 Agent、管理绑定或授权远程 hooks。重启服务保留绑定，修改 `AUTH_TOKEN` 会使原绑定失效。
- APP 凭据沿用现有连接设置的本地持久化方式。Android 后台服务自动使用新凭据。
- 当前为局域网 HTTP/WS 方案，二维码不提供加密隧道、互联网穿透或自动防火墙放行。仅在可信局域网使用。Android 开启本应用的明文网络访问以支持动态局域网 IP；iOS 声明相机和本地网络用途。

## HTTP 接口

| 接口 | 调用方 | 用途 |
|---|---|---|
| `GET /pair/` | 宿主机浏览器 | 绑定管理页面 |
| `GET /pair/info` | 宿主机浏览器 | 主机、网卡、配置状态、设备列表 |
| `POST /pair/sessions` | 宿主机浏览器 | `{serverUrl}` 创建 QR 与有效期 |
| `GET /pair/sessions/:id` | 宿主机浏览器 | `waiting / paired / expired` |
| `POST /pair/exchange` | 手机 APP | `{code, clientNonce, installationId, deviceName, platform, existingToken?}` 换取设备凭据 |
| `DELETE /pair/devices/:id` | 宿主机浏览器 | 解除绑定并断开设备 |

扫码功能使用 [mobile_scanner](https://pub.dev/packages/mobile_scanner)，二维码由后端 [node-qrcode](https://github.com/soldair/node-qrcode) 本地生成，无远程二维码服务。Android 使用插件自带的识别模型，无需首次启动下载模型。

## 验证

后端 `npm test` 包含二维码生成、来源限制、令牌隔离、刷新与过期、幂等重试、凭据持久化和实时撤销测试。APP `flutter test test/pairing_test.dart` 验证扫码协议、非法地址、过期码、交换请求和错误响应。静态检查使用 `flutter analyze`。

相机实际识别、系统权限弹窗、真实 Wi-Fi 与防火墙条件仍需手机验证。iOS 需要在 macOS/Xcode 下构建和真机验证。
