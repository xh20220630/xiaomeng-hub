01 · 背景与目标

开发者在本机运行多个 Claude Code 会话执行编码任务。任务常需长时间运行，并在关键节点（执行危险命令、修改文件）请求人工批准。开发者无法一直盯着电脑，导致任务卡在审批环节空等。

本项目在现有 claude_monitor 应用基础上扩展，使开发者能在手机上：

  • 总览全部项目：一屏看到本机所有 Claude Code 项目及其实时状态。
  • 进入项目对话：查看历史对话、工具调用与任务状态流转。
  • 远程审批：当任务请求批准时，在 App、灵动岛或锁屏直接批准 / 拒绝，任务立即继续。
  • 无需打开 App 即可处理：通过灵动岛 / 锁屏 Live Activity（iOS）或常驻通知（Android）完成最高频的「批准」动作。

核心目标：把「开发者必须回到电脑前才能让任务继续」缩短为「在手机上一次点击即可放行」，将平均审批等待时间降到分钟级以内。

02 · 名词定义与角色

名词定义
项目 Project一个 Claude Code 工作目录（cwd）。一个项目在同一时刻通常对应一个活跃会话，是首页卡片的聚合单位。
会话 Session一次 Claude Code 运行实例，含唯一 sessionId。沿用现有模型。
任务事件 TaskEvent会话生命周期中的一条事件（开始 / 工具调用 / 需审批 / 完成等），即对话与时间线的数据源。
审批请求 Approval会话在执行命令或修改文件前发起的待人工确认动作，需用户回传「批准 / 拒绝」。
小梦 KEKE/MENGApp 的 IP 形象，以表情反映任务状态，贯穿全端。
桥接服务 Bridge运行在开发者本机、接收 Claude Code Hook 事件并通过 WebSocket 推送给 App 的服务（现有 webhook server，默认端口 4820）。

03 · 技术架构与现状

现有工程为 Flutter + Riverpod，关键现状如下，新功能在此之上扩展，不做整体重构：

  • 状态管理：Riverpod。monitor.dart 持有会话与事件，负责接入 WebSocket 与 REST 初始加载；settings.dart 用 SharedPreferences 持久化服务器地址。
  • 通信：ws_service.dart 维护 WebSocket（含指数退避重连）；api_service.dart 提供 REST 初次加载 / 重同步。
  • 页面：仪表盘、会话详情、设置三屏。
  • 模型：Session 与 TaskEvent，对应桥接服务的数据行。
  • 主题：Material 3 深色主题。本次新增视觉采用 Claude Code 暖色系统（赭石 #D97757、纸色 #FAF7F1、墨色 #2C2823）。

实现前提：新功能依赖桥接服务支持「双向通信」——不仅推送事件，还要接收 App 回传的审批结果。第 05 节定义所需协议扩展，需与桥接服务一并开发。

04 · 数据模型变更

在现有 Session / TaskEvent 基础上，新增 Project 聚合与 Approval 结构。

4.1 Project（新增聚合）

首页以项目为单位展示。客户端可由会话流按 cwd 聚合得出，或由桥接服务直接下发。建议服务端下发以减少端上逻辑。

字段类型说明
projectIdString项目唯一标识（建议为 cwd 的哈希）。
nameString展示名（如 api-server），取 cwd 末级目录名。
cwdString工作目录绝对路径。
statusEnum聚合状态：running / needs_approval / waiting_input / done / ended / error。见第 12 节。
activeSessionIdString?当前活跃会话。
summaryString?一句话进度（如「编辑 src/App.tsx — 第 12 步」）。
progress{done,total}?步骤进度，用于进度条与灵动岛 12/18。
pendingApprovalApproval?非空表示有待处理审批，决定首页置顶与岛/锁屏告警。
lastEventAtint (ms)最后活动时间，用于排序与「x 分钟前」。

4.2 Approval（新增）

字段类型说明
approvalIdString审批唯一 ID，回传时携带。
sessionIdString所属会话。
kindEnumcommand（命令）/ file_edit（文件修改）。决定抽屉样式。
titleString如「执行命令」「修改文件」。
commandString?kind=command 时的命令文本。
filePathString?kind=file_edit 时的文件路径。
diffString?kind=file_edit 时的 diff（统一 diff 格式）。
riskEnum?danger / normal，danger 显示醒目警告（如 force push）。
optionsString[]可选权限档位：once / always / reject。
createdAtint (ms)发起时间，用于超时处理。

05 · 通信协议与服务端需求

沿用现有 WebSocket 通道，扩展消息类型。所有消息为 JSON，含顶层 type 字段。

5.1 服务端 → App（下行）

type载荷用途
projects.snapshotProject[]连接 / 重连后全量同步，渲染首页。
project.updateProject单项目状态变化，增量刷新卡片与灵动岛。
event.appendTaskEvent新增一条对话 / 工具调用事件，追加到详情。
approval.requestApproval发起审批 → 弹抽屉 + 推送 + 灵动岛/锁屏告警。
approval.resolved{approvalId, by}审批已在别处处理（如电脑端），端上收起对应 UI，避免重复。

5.2 App → 服务端（上行）关键新增

type载荷用途
approval.respond{approvalId, decision, scope}decision: approve/reject；scope: once/always。桥接服务据此放行或中止 Claude Code。
message.send{sessionId, text}用户在详情页回复 Claude（输入框）。
session.control{sessionId, action}action: pause/resume/open，供灵动岛 / 锁屏快捷操作。

幂等与时效：审批回传需幂等（同一 approvalId 多次响应只生效一次）；超过 createdAt 一定时长（建议可配置，默认 30 分钟）的审批标记为过期，App 端禁用按钮并提示「已过期，请回电脑处理」。

06 · 功能需求 F1 — 首页 · 项目总览 P0

替换现有仪表盘，以「按状态分组、优先级排序」呈现本机全部 Claude Code 项目。对应原型「方案 B」。

用户故事：作为开发者，我打开 App 第一眼就能看到「有没有事要我处理」，最紧急的审批永远在最上面，进行中和已完成的项目一目了然。

6.1 布局与分组（自上而下）

  • 顶栏：左侧「小梦」头像图标 + 标题「我的项目」；右侧连接状态徽标（已连接 / 重连中 / 离线），数据源自 ws_service 的 WsStatus。
  • 需要你处理：含 pendingApproval 的项目，赭石描边卡片 + 小梦审批表情 + 红点计数；整组置顶。点击进入对应项目详情。
  • 进行中：status=running 的项目，显示一句话进度 + 脉冲点。
  • 今日完成：done/ended 项目，紧凑列表 + 结果摘要（如「✓ 7 任务」「✓ 已部署」）。

6.2 交互与规则

  • 整卡片可点击 → 进入项目详情（F2），转场为水平滑入。
  • 分组标题显示实时计数；某组为空时整组隐藏。
  • 状态变化经 project.update 增量刷新，卡片在组间移动需有动效（如审批完成后从顶部移入「进行中」）。
  • 下拉刷新触发 projects.snapshot 重同步。
  • 离线时顶栏置灰并显示「未连接」，卡片数据保留为最后已知状态。

07 · 功能需求 F2 — 项目详情 · 对话与任务流转 P0

聊天式界面，复刻 Claude Code 的对话观感，叠加顶部任务步骤条。对应原型「方案 A」。

用户故事：作为开发者，我能像看聊天记录一样回看 Claude 做了什么、跑了哪些命令、改了哪些文件，并随时知道任务进行到哪一步。

7.1 顶部任务步骤条

  • 四阶段：规划 → 执行 → 审批 → 完成，始终可见、吸顶。
  • 每个节点三态：已完成（绿勾）/ 进行中（赭石实心 + 光环）/ 未开始（灰描边，未来步骤虚线）。
  • 审批被拒时，「审批」节点转为暗红 ✕、「完成」保持虚线（任务暂停）。状态映射见第 12 节。

7.2 对话消息类型

类型渲染
Claude 文本左侧浅色气泡 + 小梦头像。
用户文本右侧赭石浅色气泡。
工具调用 Bash深色代码块，标题 ⚙ Bash · 命令，下方输出（成功绿 / 失败红）。
工具调用 Edit深色块，标题 ✎ Edit · 文件，显示 +增 −删 行数。
系统状态条居中胶囊：「等待审批」「已批准」「已拒绝」等里程碑。

7.3 交互

  • 消息区按时间正序，支持上滑回看历史；新事件经 event.append 实时追加并自动滚到底（用户上滑查看历史时不强制打断）。
  • 「等待审批」状态条可点击 → 打开审批抽屉（F3）。
  • 底部输入框回复 Claude → 发送 message.send。
  • 返回键回到首页。

08 · 功能需求 F3 — 审批抽屉 P0

从详情页底部弹出的模态抽屉，背景压暗，承载最高频的审批动作。对应原型「方案 A（命令审批）」，并兼容文件修改型。

用户故事：作为开发者，当 Claude 要执行危险命令时，我能立刻看到是什么命令、风险在哪，一键批准或拒绝。

8.1 命令审批（kind=command）

  • 小梦审批表情 + 标题「小梦需要你批准」+ 项目名与动作。
  • 深色代码块展示 command 全文。
  • risk=danger 时显示警告条（如「强制推送会覆盖远端历史，不可撤销」）。
  • 两个动作：拒绝（描边）/ 批准并执行（赭石实心）。
  • 复选项「本次会话内始终允许此类命令」→ 决定回传 scope=always。

8.2 文件修改审批（kind=file_edit）

  • 显示文件路径 + diff（增行绿、删行红）。
  • 三档单选：仅本次允许 / 始终允许编辑此文件 / 拒绝并说明原因，对齐 Claude Code 权限模型。
  • 「查看完整 diff」可展开。

8.3 通用规则

  • 点击动作 → 发送 approval.respond；成功后抽屉收起、详情追加结果状态条、步骤条推进。
  • 若收到 approval.resolved（已在电脑端处理），自动收起并提示「已在其他设备处理」。
  • 审批过期 → 按钮禁用 + 过期提示。
  • 抽屉可点击背景或下滑关闭（不等于拒绝，仅暂不处理）。

09 · 功能需求 F4 — 灵动岛 Live Activity（iOS） P1

让任务状态常驻系统级灵动岛，无需打开 App 即可瞄进度、收审批。iOS 16.1+ 通过 ActivityKit 实现。

用户故事：作为开发者，我在用别的 App 时，灵动岛就能告诉我任务跑到哪了；要审批时它变橙，我点一下就能批准。

状态紧凑态展开态（长按）
运行中脉冲点 + 进度 12/18 + 小梦头像。项目名 + 当前步骤 + 进度条 + 「收起 / 打开」。
需审批橙色发光描边 + 「需批准」+ 小梦审批脸。命令文本 + 「拒绝 / 批准」按钮（岛内直接处理）。
已完成绿点 + 18/18 + 小梦开心脸。完成摘要 + 「打开会话」。
  • 岛内「批准 / 拒绝」走 approval.respond，与 App 内抽屉共享同一状态：任一处处理后，另一处实时同步。
  • 「打开 / 打开会话」深链直达对应项目详情（F2）。
  • Live Activity 内容随 project.update / approval.request 通过 push token 远程更新（APNs Live Activity push）。

平台约束：灵动岛按钮交互依赖 App Intents（iOS 17+）；iOS 16 仅支持点击进入 App。Live Activity 远程更新需后端具备 APNs 推送能力，需在桥接服务或中转后端实现。

10 · 功能需求 F5 — 锁屏 Live Activity / 安卓常驻通知 P1

10.1 iOS 锁屏 Live Activity

  • 锁屏常驻卡片：小梦头像 + 项目名 + 一句话状态 + 进度条 + 快捷操作。
  • 运行 / 完成态：「关闭 / 打开会话」；需审批态：命令 + 「拒绝 / 批准并执行」。
  • 与灵动岛、App 内抽屉同源状态，息屏抬手即见、可直接批准。

10.2 Android 等价实现 P1

Android 无灵动岛，用以下能力达成等价体验：

  • 常驻前台通知（ongoing notification）展示进度条 + 状态，对应「紧凑/锁屏」体验。
  • 通知快捷操作按钮「批准 / 拒绝」，通过 Notification Action 直接回传 approval.respond，无需进入 App。
  • 需审批时升级为 高优先级 + 提示音/震动 的 Heads-up 通知。
  • 沿用现有 services/notifications 工厂，扩展带 action 的通知构建与回调处理。

11 · 功能需求 F6 — IP 形象「小梦」状态系统 P2

统一的角色资产，以表情映射任务状态，强化品牌记忆并降低状态识别成本。

资产对应状态使用位置
主视觉立绘—启动页、关于页、空状态。
头像（半身）通用首页标题、聊天气泡、卡片头像。
运行中表情running进行中卡片、灵动岛、通知。
审批表情needs_approval需处理卡片、抽屉、岛/锁屏告警。
完成表情done完成态卡片、岛/锁屏。
出错/离线表情error/idle拒绝后、连接断开、空闲。
App 图标—桌面图标、应用商店。
  • 资产以透明 PNG 提供（≥1024px），已随项目交付，按状态枚举映射，禁止在不匹配状态混用。
  • 建议封装 MascotImage(status) 组件统一取图，便于后续替换为 Lottie 动效。

12 · 任务状态机

项目 / 会话状态统一收敛为下列枚举，驱动所有 UI（卡片、步骤条、岛、锁屏、小梦表情）。

状态步骤条触发 / 含义
running 运行中执行（进行中）会话正在执行任务。
needs_approval 需审批审批（进行中）收到 approval.request，等待用户决定。
waiting_input 等待输入执行（暂停）Claude 需要用户补充信息。
done 已完成完成（绿勾）批准后任务成功结束。
rejected/paused 已拒绝/暂停审批（暗红 ✕）用户拒绝，任务暂停等待后续指令。
ended 已结束完成会话正常终止。
error 出错/离线当前步置错误会话异常或桥接断连。

关键流转：running → needs_approval →（批准）running → done；或 →（拒绝）paused。所有端在收到 approval.respond 的回执后必须同步刷新。

13 · 非功能需求

  • 实时性：事件从桥接到端上展示延迟 < 1s（同局域网）。
  • 连接韧性：沿用 WebSocket 指数退避重连；重连后必须 projects.snapshot 全量校正，避免状态漂移。
  • 离线表现：断连时保留最后已知状态并明确标识；审批按钮在断连时禁用。
  • 安全：审批是高危操作，上行通道需鉴权（建议配对 token / 局域网内一次性配对码）；审批回传需幂等 + 时效校验，防重放。
  • 电量与后台：Live Activity / 常驻通知更新需节流，避免高频推送耗电。
  • 可达性：命中目标 ≥ 44px；状态不仅靠颜色区分（同时用图标 / 文案）。

14 · 验收标准与里程碑

14.1 关键验收标准

  • 首页能按状态分组展示全部项目，审批项置顶并实时计数。
  • 进入项目可见完整对话（含 Bash / Edit 工具块）与四阶段步骤条。
  • App 内、灵动岛、锁屏 / 通知任一处批准 / 拒绝，桥接服务正确放行 / 中止 Claude Code，且三处状态同步。
  • 审批幂等、过期、已在他端处理三种边界均有正确反馈。
  • 断连重连后状态自动校正无残留。

14.2 建议里程碑

阶段范围交付
M1F1 + F2 + 协议下行首页总览 + 项目详情对话，只读监控可用。
